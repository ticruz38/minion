## Codebase Patterns
- Use `zod` for request validation in API endpoints
- Zod errors use `.issues` array, not `.errors` - each issue has `path` and `message`
- API endpoints return `{ success: boolean, message: string, ...data }` format
- Use `safeParse` for Zod validation to avoid throwing
- Environment variables should be accessed via `process.env`
- Check for environment variables and degrade gracefully (demo mode)
- Redis client is initialized lazily (singleton pattern)
- Use SvelteKit's `json()` helper for responses
- Use `@sveltejs/kit` `error` helper for HTTP errors
- **Always use `typeof window !== 'undefined'` checks when accessing `window` in components** - SvelteKit SSR will fail otherwise
- Use `onMount` for client-side only code like event listeners
- **Modal patterns**: Use Svelte transitions (`fade`, `scale`) for smooth open/close animations
- **CSS backdrop-filter**: Use `backdrop-filter: blur()` with `-webkit-backdrop-filter` fallback for modal overlays
- **Svelte custom events**: Use `createEventDispatcher` for parent-child communication
