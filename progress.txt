## Codebase Patterns
- **VM Creation API:** Uses Zod for validation with detailed per-channel schemas (telegram, discord, whatsapp)
- **UUID Correlation:** Frontend generates UUID v4 for `id` field; backend uses this for Redis correlation
- **HTTP Status Codes:** API returns 202 (Accepted) for async processing, not 201 (Created)
- **Redis Channels:** `clawd:commands` for publishing requests, `clawd:responses` for status updates
- **TypeScript:** Use strict typing for channel configs with discriminated unions (`enabled: true`)
- **Test Pattern:** Mock `/api/vms` route to verify request schema and response handling
- **Redis Pub/Sub:** Use separate Redis connections for subscriber (receives messages) and publisher (sends messages)
- **Memory Leak Prevention:** Always set auto-unsubscribe timeouts for Redis subscriptions; clear timeouts on manual unsubscribe
- **Vitest Pattern:** Use vi.mock() at top-level to mock dependencies like ioredis; extract mock instances via vi.mocked()
